# Seed validation — Pretty Chat

The seed-validation contract `/dev-copilot:validate-seeds PrettyChat <flavor>` runs. The command
supplies the loop (clean tree, one date, status, derive, rule, apply, gate, hand-back) and its
standing rules. This file supplies Pretty Chat's procedure. The headings below are the interface the
command reads, so keep their names.

**What Pretty Chat seeds.** No game ids. What it takes from the client is UI strings, in two places:

- **The keys the code depends on.** The 79 GLOBALNAMEs in `defaults/Defaults.lua`, each a Blizzard
  format string the addon rewrites in `_G`. A key the build no longer has is a dead settings row; a
  key whose conversions changed can make a default ask for an argument the game does not pass,
  which raises on every chat line of that kind. This is the check that matters.
- **The copy.** `GlobalStrings/GlobalStrings.lua` and its chunks, a copy of the client's own
  GlobalStrings, never loaded and never shipped ([global-strings.md](./global-strings.md)). Its one
  reader is `tests/test_defaults.lua`, which checks every default's conversion sequence against
  Blizzard's. So the copy is a test fixture mirroring one Retail build, and it is generated data:
  it is regenerated whole and is never curated key by key.

The source is the client's `GlobalStrings` DB2 on wago.tools (`BaseTag`, `TagText_lang`, `Flags`).
Rows with `Flags` bit `0x1` are the FrameXML strings, the set the copy holds. The tool and its tests
are `tools/seeds/globalstrings.py` and `tools/seeds/test_globalstrings.py`. Each run ends in a frozen
bundle under `docs/seed-research/<date>-<flavor>/`. The first runs are
`docs/seed-research/2026-11-15-retail/` and `docs/seed-research/2026-11-15-forever/`.

## Flavors

| Flavor | Source | Seed files | Tools |
| --- | --- | --- | --- |
| `retail` | wago.tools product `wow` (Retail live), table `GlobalStrings` | the keys `defaults/Defaults.lua` depends on (checked); `GlobalStrings/GlobalStrings.lua` and `GlobalStrings/GlobalStrings_0NN.lua` (generated, regenerated by `apply`) | `tools/seeds/globalstrings.py`, `tools/split_globalstrings.py` |
| `forever` | wago.tools product `wowf` (WoW Forever), table `GlobalStrings` | the keys `defaults/Defaults.lua` depends on (checked); no copy of its own | `tools/seeds/globalstrings.py` |

Forever has no copy because one format-string list serves both clients, a decision recorded in
`docs/ARCHITECTURE.md` ("Per-client features"). The `forever` flavor is what re-measures that
decision on every Forever build. It never builds a second copy: that would re-open a recorded
decision.

## Rules

- **Only the tools write the seed files.**
  - `GlobalStrings/GlobalStrings.lua` is written only by `globalstrings.py apply`. The chunks are
    written only by `tools/split_globalstrings.py`, which `apply` runs.
  - `defaults/Defaults.lua` is authored. The tool reads it and never writes it. A flag ruled `fix`
    is a code change for the owner, made and reviewed like any other.
- **The copy is never ruled key by key.** Its delta against the build (new, gone and changed keys)
  is reported in the bundle's `DIFF.md` and applied whole, by regeneration. The copy's exemption
  from `layout-§1`'s 1500-line cap holds only while it is generated
  ([global-strings.md](./global-strings.md#the-cap-exemption), condition 1). A copy pruned or kept
  back key by key would be curated, and the exemption would lapse. So the run proposes no
  candidates for it, and `candidates.json`'s `candidates` list is always empty.
- **Rulings are data.** They live in `tools/seeds/retail_rulings.json` and
  `tools/seeds/forever_rulings.json`, written only by `globalstrings.py rule`. A ruling is keyed
  `<kind>:<GLOBALNAME>` and never by build. It holds until the thing it ruled on stops being
  proposed. A rulings file appears with its flavor's first flag. There is none yet.
- **Flags, over every key `defaults/Defaults.lua` depends on**, ruled `keep` or `fix`:
  - `gone`: the build has no FrameXML row for the key.
  - `breaks`: the default's conversion sequence is not a positional prefix of the build's. This is
    `tests/test_defaults.lua`'s rule (`NS.SequenceIsPrefix`), ported to Python and run against the
    build. `test_globalstrings.py` pins the port to the Lua case: both find the same four
    sanctioned truncations.
  - `signature`: the build's conversions differ from the reference copy's, but the default is
    still a prefix of them.
  - `reworded`: the build's text differs from the reference copy's, with the same conversions.

  The reference copy is `GlobalStrings/GlobalStrings.lua` on both flavors. For `retail`, that is the
  previous build. For `forever`, it is the Retail list that `docs/ARCHITECTURE.md` measured as
  serving both clients.
- **Precedent, in this order, never re-litigated:**
  1. a ruling already in the flavor's rulings file;
  2. `SANCTIONED_TRUNCATIONS` in `tests/test_defaults.lua`: four defaults that drop trailing
     arguments on purpose (`LOOT_DISENCHANT_CREDIT`, `COMBATLOG_DISHONORGAIN`, `OPEN_LOCK_OTHER`,
     `OPEN_LOCK_SELF`). They are not `breaks`, and they must not be "fixed";
  3. `docs/ARCHITECTURE.md` "Per-client features": one list, no client branch. A key missing on
     Forever is tolerated at runtime (`SnapshotOriginals` records nil and `ApplyStrings` restores
     nil, PC-R-07);
  4. the curated order and labels in `defaults/Defaults.lua` (item 020, PRC-L01).
- **How to rule a flag.**
  - `gone`: on `retail`, the setting is dead. Rule `fix` unless the owner has decided to keep the
    row. On `forever`, rule `keep` when the string is a Retail-only feature (PC-R-07 already
    tolerates it). Rule `fix` when Forever has the same message under another key.
  - `breaks`: always `fix`. The default raises in game.
  - `signature`: `keep` when the default is still correct as the prefix it is (record why). `fix`
    when it should now show the new argument.
  - `reworded`: `keep` unless the new text changes what the row's label or the default's wording
    should say.
- **Privacy.** No player name, realm or GUID goes into a bundle, a ruling or a commit.

## Flavor: retail

### Status

```sh
python3 tools/seeds/globalstrings.py status --flavor retail
```

Prints `CURRENT <build> (<bundle>)`, or `NEW <build> (last ruled <build>, <bundle>)`, comparing the
live `wow` build with the newest `*-retail` bundle under `docs/seed-research/`.

### Freeze and derive

```sh
python3 tools/seeds/globalstrings.py derive --flavor retail --build <build> --bundle docs/seed-research/<date>-retail --date <date>
```

It downloads about 1.9 MB on a new build, cached in `tools/seeds/.cache/` (git-ignored). It freezes
the table gzipped into `raw/GlobalStrings.csv.gz` (about 0.6 MB) and writes `candidates.json`,
`SOURCES.md` and `DIFF.md`. It runs a coverage gate: six sentinel keys and a 20,000-row floor.
**If the gate fails, stop.** The fix is in the fetch, never in the sentinels. `--replay` re-derives
from `raw/` alone, offline. Report the copy delta (new, gone, changed), the flag count and the
unruled count.

### Rule

```sh
python3 tools/seeds/globalstrings.py check --bundle docs/seed-research/<date>-retail
python3 tools/seeds/globalstrings.py rule --tsv <scratchpad>/rulings.tsv --bundle docs/seed-research/<date>-retail
```

`check` lists every unruled flag, with the default's, the build's and the reference's conversion
sequences. It must print `OK` after `rule`. The TSV is `key<TAB>ruling<TAB>reason`, one line per
flag. A run with no flags has nothing to rule, and `check` prints `OK` straight away.

### Apply

```sh
python3 tools/seeds/globalstrings.py report --bundle docs/seed-research/<date>-retail --date <date>
python3 tools/seeds/globalstrings.py apply  --bundle docs/seed-research/<date>-retail --date <date>
```

`report` writes `RULINGS.md`. `apply` refuses while anything is unruled. It then regenerates
`GlobalStrings/GlobalStrings.lua` from the bundle's `raw/` alone: the banner, a blank line, one
`KEY = "...";` line per FrameXML row (`_G["..."]` for a key that is not a Lua identifier), sorted
the way the copy always was, CRLF, and the `glyph: data` begin and end pair around every
`GLYPH_DATA_KEYS` entry in `tools/split_globalstrings.py`. Then it runs the splitter, which re-cuts
the chunks (900 entries each) and asserts that `PrettyChat.toc` still does not load them. A second
`apply` changes nothing. Any `fix` ruling is printed as owed work. `apply` does not edit
`defaults/Defaults.lua`.

### After

- **`tests/prose_waivers.lua`.** The chunk boundaries move, so the per-file waivers move with them.
  The prose gate names each line that lost its waiver. Re-list exactly the words each
  `GlobalStrings/` file carries, and roll the "Measured" note. A new British word arriving with the
  build is waived the same way, per file and per word. It is Blizzard's English.
- **The glyph guard** (`tests/test_glyphs.lua`) names any new value holding a character a shipped
  face cannot draw. Add its key to `GLYPH_DATA_KEYS` in `tools/split_globalstrings.py`, and re-run
  `apply`.
- **Counts in the docs.** Roll the copy's line count and the chunk count wherever they are quoted:
  `docs/ARCHITECTURE.md` (the 1500-line census), `docs/global-strings.md`, `docs/module-map.md`,
  `docs/testing.md` (the cap gate), `GlobalStrings/README.md` and `DEPENDENCIES.md`.
- **A flag ruled `fix`.** Change `defaults/Defaults.lua` in the same change, or open an issue if
  the owner defers it. Add a smoke check to `docs/smoke-tests.md` for each default that changed,
  with its *Pending sign-off* note. A run that changes no default adds none: the copy is not shipped,
  so regenerating it changes nothing a player sees.
- Write the bundle's `ANALYSIS.md` by hand, in the 2026-11-15 bundle's shape: what changed between
  the builds, what was flagged and how it was ruled, and what a later run should re-check.

### Stage

`GlobalStrings/GlobalStrings.lua`, `GlobalStrings/GlobalStrings_*.lua` (a chunk that appeared or
went away included), `tools/seeds/retail_rulings.json` (once it exists),
`docs/seed-research/<date>-retail`, `tests/prose_waivers.lua`, plus any `tools/split_globalstrings.py`,
`defaults/Defaults.lua`, smoke or count edits. Commit message:
`Seeds (retail): GlobalStrings re-validated against <build> (<date>)`.

## Flavor: forever

### Status

```sh
python3 tools/seeds/globalstrings.py status --flavor forever
```

Prints `CURRENT <build> (<bundle>)` or `NEW <build> (...)`, comparing the live `wowf` build with the
newest `*-forever` bundle.

### Freeze and derive

```sh
python3 tools/seeds/globalstrings.py derive --flavor forever --build <build> --bundle docs/seed-research/<date>-forever --date <date>
```

It runs the same table, cache and coverage gate as `retail`, on Forever's own product. It writes no
copy delta, because Forever has no copy. The flags compare each dependent key on the Forever build
with the Retail copy, so run `retail` first in a session that runs both, and the reference is then
the current Retail build. Report the flag count and the unruled count.

### Rule

```sh
python3 tools/seeds/globalstrings.py check --bundle docs/seed-research/<date>-forever
python3 tools/seeds/globalstrings.py rule --tsv <scratchpad>/rulings.tsv --bundle docs/seed-research/<date>-forever
```

Nuances:

- **A `gone` key is the reopen trigger** `docs/ARCHITECTURE.md` names ("a string missing or reworded
  on Forever"). Rule it, then update that paragraph's measurement in the same change.
- **A `reworded` key on Forever** is often the client's own wording (Forever's strings say
  *Account* where Retail's say *Warband*). Rule `keep` unless the default copies Retail wording that
  Forever players would read as wrong.
- **No Forever combat logs or in-game captures are needed.** The build's table is the whole evidence
  for a UI string.

### Apply

```sh
python3 tools/seeds/globalstrings.py report --bundle docs/seed-research/<date>-forever --date <date>
python3 tools/seeds/globalstrings.py apply  --bundle docs/seed-research/<date>-forever --date <date>
```

`apply` refuses while anything is unruled. It then writes nothing (Forever has no copy) and prints
any `fix` ruling as owed work.

### After

- Roll the measurement in `docs/ARCHITECTURE.md` "Per-client features" to name this bundle and its
  build.
- A flag ruled `fix` is handled as in `retail`'s *After*, including a FOREVER smoke check and its
  *Pending sign-off* note.
- Write the bundle's `ANALYSIS.md` by hand, in the 2026-11-15 bundle's shape.

### Stage

`docs/seed-research/<date>-forever`, `tools/seeds/forever_rulings.json` (once it exists),
`docs/ARCHITECTURE.md`, plus any `defaults/Defaults.lua` or smoke edits. Commit message:
`Seeds (forever): GlobalStrings re-validated against <build> (<date>)`.

## Gate

```sh
~/.claude/dev-copilot/bin/ka0s-bounded lua tests/run.lua
KA0S_KIT_CLIENT=forever ~/.claude/dev-copilot/bin/ka0s-bounded lua tests/run.lua
~/.claude/dev-copilot/bin/ka0s-bounded luacheck .
python3 -m pytest -q tools/seeds
```

luacheck must report 0 warnings and 0 errors, and every suite must report 0 failed. Run the suites
after staging: the end-of-line and documentation gates read `git ls-files`, so a new file that is
not staged yet goes unchecked. `tools/seeds/test_globalstrings.py` checks four things. The copy
re-renders byte for byte. The copy equals the newest Retail bundle's build. The Python prefix rule
agrees with `tests/test_defaults.lua`. Every flag in each flavor's newest bundle is ruled.

## Notes

- **Bundle size.** About 0.6 MB per flavor (one gzipped table) plus `DIFF.md` and
  `candidates.json`. One bundle per patch is acceptable.
- **The copy's old source.** Until 2026-11-15 the copy was taken by hand from townlong-yak's
  FrameXML `GlobalStrings.lua`. The regeneration from DB2 reproduces that file's format byte for
  byte: every key whose value did not change kept its line, as `TestRepo` pins. So the source moved
  without changing the format.
- **DB2 text carries Lua escapes.** `TagText_lang` mixes raw CR/LF with `\n`, `\"` and decimal
  escapes such as `\32` (a trailing space). The tool compares decoded values. An unknown escape
  keeps its backslash: `PARTY_PLAYER_CHROMIE_TIME_FMT`'s `\%` is a literal backslash at runtime, as
  the old copy had it.
- **Shared helper.** Whether the build pin, cache, bundle and rulings should become a shared
  helper is LibKa0s#91. Until it decides, this tool copies AuraMaster's pattern and imports nothing
  across repos.
