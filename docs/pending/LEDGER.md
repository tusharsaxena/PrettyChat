# Pending-items ledger

Decision record for pending items in this addon — TODO/FIXME markers, unexecuted audit and
review plan steps, doc open questions, open GitHub issues, and recorded-but-unacted Claude
memory. Maintained by `/wow-addon:pending-audit`; do not hand-edit rows it owns.

Each run re-discovers pending items and matches them against this table by **ID + evidence
hash**. A `done` or `wont-do` row closes the question permanently — the item is not raised
again. A `deferred` row keeps the item alive but quiet: it reappears only as a collapsed count.
If an item's evidence text later changes, its hash changes, and it is re-interviewed as a
changed item even if it was previously closed.

## Notation

| Marker | Value | Meaning | Re-surfaces? |
|---|---|---|---|
| 🟢 | `done` | Implemented this run | No — closed |
| 🔵 | `wont-do` | User decided it will never be done | No — closed |
| 🟡 | `deferred` | Not now; still on the books | Yes, as a collapsed count |

Green is resolved. Blue is a deliberate, settled close — declining to do something is a
decision, not a failure. Yellow is the only row type still demanding attention, so a column of
yellow is this file telling you what is left. There is deliberately no red: nothing here is an
error state.

## LibKa0s adoption — 2026-08-02

The decisions taken while adopting **LibKa0s v1.3.1** (`Core = 3`, `DebugLog = 6`, `Slash = 5`,
`Options = 5 / OptionsWidgets 5 / OptionsScroll 2`, `Perf = 5 / PerfPanel 3`). Written as each call
was made rather than at the end: the ones that get lost are the decisions that felt obvious at the
time.

Hand-maintained, unlike the table above — `/wow-addon:pending-audit` does not own these rows.

| ID | Module | Decision | Rationale |
|---|---|---|---|
| LIBKA0S-01 | testkit | 🟢 adopted, with two documented deviations | `tests/_kit/framework.lua` is the registry, the assertions, the runner and the `--list` renderer; every suite moved to `_G.PC_TEST` and `t.eq`/`truthy`/`falsy`/`nilv` are now aliases onto `Kit.assertEqual`/`assertTrue`/`assertFalse`/`assertNil`. **`tests/loader.lua` survives** as an instance factory rather than deferring to `tests/_kit/loader.lua`: the kit builds one shared environment whose `__newindex` writes through to the real `_G`, and this addon's entire feature is rewriting `_G[GLOBALNAME]` — half the suite asserts on what landed there, per instance. `tests/wow_mock.lua` is a **thin extender** over `mock_base.lua` with fifteen documented overrides. The kit's missing isolated-environment mode is reported upstream. |
| LIBKA0S-02 | Core | 🟢 adopted in full | Printer, `SafeToString`, `IsConcatSafe`. `NS.Util.SafeToString` is bound to Core's own function object, not wrapped, so a host copy cannot grow back beside it. `sep = ""` because `Const.PREFIX` carries its own trailing space. `SKIN` / `MakeCloseButton` are reached through DebugLog rather than directly; this addon draws no window of its own. |
| LIBKA0S-03 | DebugLog | 🟢 adopted in full; `core/DebugLog.lua` (424 lines) deleted | No `skin`, `applySkin` or `makeCloseButton` passed. The console's 12px `UI-Tooltip-Border` becomes the **normative** Ka0s window edge (standalone-windows-§2, Core minor 3) — a visible change, and the point of it: the console now matches every other Ka0s console rather than only this addon. |
| LIBKA0S-04 | Options | 🟢 adopted; `OpenConfig` delegates to `OpenOptionsPanel` | Two host diagnostics went with the old body: a gray notice on an explicit `false` from `Settings.OpenToCategory`, and a one-time "could not auto-expand the sub-tree" hint. The library reports neither. Keeping them meant a **second open path around the library's combat gate**, which options-ui-§2 forbids outright, so both are accepted losses. Pinned as silence in `tests/test_lifecycle.lua` so the decision is visible in the suite and not only here. |
| LIBKA0S-05 | Options / DebugLog | 🔵 accepted narrowing of the translatable surface | `"Defaults"`, `"Debug console"` and the console-checkbox tooltip left `locales/enUS.lua` because they are `lib.STRINGS` now. LibKa0s ships no locale files, so a translator restores them by passing a **plain** table of just those keys as the module's descriptor `L` — never `NS.L` itself. Recorded in `locales/enUS.lua`'s own header so a translator finds it where they will look. |
| LIBKA0S-06 | OptionsWidgets | 🔵 declined — the per-string 40/60 editor stays host-drawn | The documented PC-23 deviation, re-checked against `RenderGrid` before being kept: `RenderGrid` lays items out at `HALF` (0.5) or full width and offers no third ratio, so it cannot express 40/60 either. The block is a domain-specific three-row control, not a row of independent settings. `AttachTooltip`, `AddSpacer`, `EnsureScroll` and `SECTION_HEADING_H` inside it are all the library's. |
| LIBKA0S-07 | Options / Slash | 🔵 declined — `RestoreDefaults`, `RestoreAllDefaults` and `CliResetAll` | All three are row-by-row, and this schema has ~171 rows across nine categories. Driving a category reset or a global reset through them would run `ApplyStrings` once per row and emit one `[Set]` line per row into a 500-line console buffer — the per-item spam debug-logging-§9 forbids. `PrettyChat:ResetCategory` and `:ResetAll` stay the bulk implementations, one pass and one `[Reset]` summary each. `CreatePanel`'s `OnDefault` forwards to them, so the Settings window's footer control and the header Defaults button are still **one** body. |
| LIBKA0S-08 | Slash | 🟢 adopted; second host on the `format` hook (Slash minor 5) | The hook carries the `\|` → `\|\|` doubling that keeps a format string's color escapes readable as text instead of coloring the chat line. First use of it on a row type the library **can** already render — the shape the adoption prompt flagged as untried. It delegates to `lib.FormatValue` first and only post-processes strings, so the empty-string case comes back as the library's `(none)` (slash-commands-§5), which this addon did not do before. Its documented precedence over `colorDecode` is still unexercised: this addon passes no color codecs. |
| LIBKA0S-09 | Slash | 🟢 adopted the `parse` hook — for a **library gap**, not an exotic type | `lib.ParseValue` splits the remainder on whitespace and `parseString` returns `args[1]`, so `/pc set <path> You receive loot: %s` would store `"You"`. Every value in this schema is a format string containing spaces. slash-commands-§6 names `parse` as the sanctioned seam, so this is a host concern by the letter — but the underlying shortfall (a free-text row cannot hold a space) is reported upstream, because it is not specific to this addon. |
| LIBKA0S-10 | Slash | 🟢 **convergence #1 adopted** — breaking | `/pc reset <Category>` → `/pc reset <path>`. The capability did not move, only its CLI route: each category page's Defaults button still resets a category and `/pc resetall` still resets everything. Shipped with a **deprecation message**, not silently — a bare category name is intercepted and answered with both replacements, because the old form still parses as something and would otherwise come back "Setting not found: Loot". |
| LIBKA0S-11 | Slash | 🟢 **convergence #2 adopted** | The landing page renders its command rows through `Sl:LandingRows()`. The panel's own formatter had double spaces around the em dash, an explicitly white-wrapped dash and a bare description; all three collapse. Pinned in bytes in both suites so the two surfaces cannot drift again. |
| LIBKA0S-12 | Perf | 🔵 **declined**, on two independent structural grounds | **(1) There is no hot path at all.** A whole-repo sweep of `core/ defaults/ modules/ settings/ locales/` finds zero `RegisterEvent`, zero `OnUpdate`, zero `C_Timer`, zero ticker and zero repeating timer. The addon's entire runtime cost is one `_G[GLOBALNAME]` write pass at `OnEnable` and one more per settings change; after login it does not execute again. Every declared bucket would read `0.000` by construction. **(2) `suspend` would change what the user sees mid-fight.** Making PrettyChat inert means restoring Blizzard's originals for the duration of a combat-gated measurement window and re-applying afterwards — a visible flip of the player's chat formatting in the middle of the fight being measured, for a capture that can only ever report zero. `<Addon>PerfDB` is therefore **not** declared in the TOC and no `core/PerfSetup.lua` exists. |
| LIBKA0S-13 | library finding | 🟡 reported, not worked around | `DebugLog` tints the title-bar state toggle `0.30/0.85/0.30` (ON) and `0.90/0.30/0.30` (OFF), while debug-logging-§5 mandates the chat ack at `40ff40`/`ff4040` **and states that the two mirror each other**. `40ff40` is `0.25/1.00/0.25`. They no longer match exactly. The descriptor has no hook for it by design — it is the library's widget — and standalone-windows-§2 says changing a shared window value is a **standard** change, not a library one. Left as a finding rather than patched locally. |
| LIBKA0S-14 | library finding | 🟡 reported | `LibKa0s-Options-1.0` exposes no accessor for the Blizzard category it registered, nor its ID. `__panels()` / `__panelFor()` reach a ctx but not the category. A host that wants its own open path — which this addon had, with two extra diagnostics — cannot get the handle without duplicating registration. That is what forced LIBKA0S-04 to be a loss rather than a re-wire. |
| LIBKA0S-15 | kit finding | 🟡 reported | `testkit/framework.lua` carries `assertEqual` but no `assertNotEqual`. This repo's suites use `neq`, which is now a thin `Kit.fail` wrapper in `tests/run.lua` rather than a private assertion. |
| LIBKA0S-16 | repo hygiene | 🟢 done — 2026-08-02, and the diagnosis was the whole job | Seventeen tracked files held **LF** in the working tree while `.gitattributes` pins `* text=auto eol=crlf`: `README.md`, the ten `GlobalStrings/GlobalStrings_0NN.lua` chunks, the frozen `docs/reviews/2026-05-02/` bundle and `media/fonts/OFL.txt`. **`git add --renormalize .` was the wrong tool and would have reported success.** `git cat-file -p HEAD:<path>` shows every one of those blobs was *already* LF — which is git's correct normalized storage — so the index and every commit were right all along and there was nothing to renormalize. The drift was **working-tree-only**, and it is invisible precisely because the clean filter turns an LF working file back into an LF blob, so `git status` reads clean either way. The fix is to make git re-materialize the files through the smudge filter: delete the paths, `git checkout -- .`. All seventeen now read CRLF, all seventeen are byte-identical modulo line endings (CR-stripped md5 compared before and after), and `git status` is still clean — **no commit, because the repository never held the defect**. Anyone whose checkout shows this again should re-run that, not renormalize. |
| LIBKA0S-17 | Options | 🟢 accepted reversal of an earlier in-code decision | `settings/Panel.lua` created every canvas frame anonymously, with a comment citing "keep them off `_G`". `mainPanelName` is the one descriptor field `LibKa0s-Options-1.0` validates, and it **raises** rather than defaulting, because an anonymous main canvas is a frame `/framestack` cannot attribute and two addons can collide on. The main canvas is now `PrettyChatOptionsPanel`; the nine sub-pages stay anonymous. |
